## Attention implementation

`SparsePrefill.forward_fa4` in `sm120_attn/sparse_prefill.py` runs the FA4 CuTe SM90 forward with
per-query-head lists over 128-row query tiles and 64-token KV blocks. Selection uses cached key-block
means, retains tau of the estimated attention mass and always includes diagonal and sink blocks.
Fully visible blocks and causal-boundary blocks use separate lists.

`sm120_attn/select_fused.py` combines masked softmax, mass-threshold selection, diagonal/sink forcing
and list packing in one Triton kernel: 1.27 → 0.63 ms per call at 8K × 64K.

`tools/patch_fa4.py` applies four patches to the installed `flash_attn/cute` package:

1. Read block-sparse K/V through the page table without gathering the full history.
2. Prefetch the next block-list entry in the producer warp.
3. Skip the mask function on fully visible blocks (-6.6% kernel time at 8K × 256K).
4. Launch tiles longest-list-first (-15% kernel time on skewed lists at 256K).

The sorted scheduler uses one CTA per tile. A persistent multi-tile grid caused register spills and was
6× slower. [Nsight Compute measurements](validation/h200-ncu-fa4sparse-vs-dense.md).

The vLLM hook uses the paged path when the KV page size is a multiple of 64 and the cache is contiguous
(e.g. `--block-size 1024`). Otherwise it gathers K/V. Cached block means are rebuilt if a request's
chunk history is discontinuous. Short chunks and decode requests use dense attention.

## Two-GPU prefill/decode serving

Prefill: GPU 4, sparse FA4 + FP8 GEMM. Decode: GPU 5, dense FA3 + FP8 GEMM.
NIXL 1.5.2 transfers KV and GDN state over UCX/NVLink; a proxy routes requests P → D.
Both engines require `VLLM_SSM_CONV_STATE_LAYOUT=DS`, disabled prefix caching and matching `--block-size`.
The connector's strided cache layout uses the gathered FA4 path.

Smoke test (2026-11-01): one 64K request, 64 decode tokens, first request including JIT and warm-up.
TTFT 11.55 s; mean / p99 TPOT 10.3 / 17.3 ms. First generated tokens matched the single-instance runs.

Concurrency sweep (2026-11-01): simultaneous requests of the given length, 256 output tokens each,
one warm-up burst followed by one measured burst. TTFT is the mean / maximum across requests;
TPOT is the mean of per-request means / maximum per-request p99. First generated tokens matched the
single-instance runs in every row. Raw records: `$H200_WORK/pd/bench-pd-184135/`.

| input | concurrency | TTFT mean / max | TPOT mean / p99 | wall |
|---|---:|---:|---:|---:|
| 64K | 1 | 4.87 s | 11.0 / 17.6 ms | 7.7 s |
| 64K | 2 | 7.44 / 9.43 s | 10.9 / 18.8 ms | 12.2 s |
| 64K | 4 | 12.2 / 18.6 s | 10.8 / 24.3 ms | 21.4 s |
| 256K | 1 | 29.3 s | 12.5 / 25.6 ms | 32.5 s |
| 256K | 2 | 43.4 / 57.1 s | 13.3 / 24.9 ms | 60.5 s |
| 256K | 4 | 71.7 / 113.1 s | 13.4 / 26.0 ms | 116.6 s |

Prefills queue serially on P; mean decode TPOT stays at 11–13 ms under this load.
Single-request TTFT is within 5% of the co-located 4.66 / 28.8 s measurements at 64K / 256K.

## Reproduce

```bash
bash scripts/h200/setup_env.sh
source scripts/h200/env.sh
python scripts/h200/check_env.py --jit
python tools/patch_vllm.py --target "$(python -c 'import vllm,os;print(os.path.dirname(vllm.__file__))')"
bash scripts/h200/build_prompts.sh
CUDA_VISIBLE_DEVICES=4 TAU=0.95 bash scripts/h200/final_matrix.sh
TAU=0.95 bash scripts/h200/quality.sh
CUDA_VISIBLE_DEVICES=4 python tests/test_sparse_prefill_fa4.py --big
CUDA_VISIBLE_DEVICES=4 python tests/test_sparse_prefill_fa4_paged.py
```

PD serving requires the proxy script at the path configured in `scripts/h200/pd_serve.sh`.

```bash
bash scripts/h200/pd_serve.sh start
bash scripts/h200/pd_serve.sh wait
LENGTHS=65536,260096 CONCS=1,2,4 bash scripts/h200/pd_bench.sh
bash scripts/h200/pd_serve.sh stop
```

Prompts, logs and benchmark outputs are stored under `H200_WORK`; checked-in records are in `validation/`.
